PR #30 Review — c_spec conditioning
Status: Not ready to merge. CI is red (4 test failures + 1 lint failure).
What it does (correctly)
The code plumbing is sound. Three changes:
1. trainer.py: dit(z_t, t) → dit(z_t, t, c_spec=c_spec) — passes the spectral-chart vector to the DiT during training, plus propagates cfg_dropout to the model.
2. inference.py: _sample_and_decode gains c_spec_override, forwarded to sample_ddim → DiT. generate_sound_bank gains target_c_spec. condition_on_audio extracts c_spec from the source audio.
3. New test file covering divergence, the z_init/c_spec conflict guard, and the cfg_dropout guard.
The mutual-exclusivity guard (z_init + c_spec_override → ValueError) and the device fix on torch.Generator(device=device) are both good defensive catches.
Why CI fails
Lint: tests/test_c_spec_conditioning.py needs ruff format — 1 file unformatted. Trivial fix.
Tests (4 failures): The divergence tests (test_conditioned_bank_differs_from_unconditioned, test_two_different_c_specs_produce_different_outputs) assert that different c_spec vectors produce different audio on a freshly-initialized, untrained DiT. They produce bit-identical output instead. Root cause:
1. With random init, spec_proj weights are near-zero, so c_spec has negligible influence on the DDIM trajectory vs. the seeded initial noise.
2. The decoder re-derives c_spec post-hoc from the generated z (a = z.mean(dim=2); c_spec = prior.chart_energy_descriptor(a) in _sample_and_decode). So even if the DiT produced a slightly different z, the decoder self-corrects toward its own c_spec — washing out residual differences.
These tests can only pass after training when spec_proj has learned to meaningfully steer the latent. The PR's acceptance-criteria table marks them ✅, but CI proves otherwise. The tests need either a trained fixture or a different assertion (e.g. assert the DiT's intermediate v_pred differs given different c_spec, which doesn't require a converged trajectory).
Impact on LSD Studio
No automatic benefit. Our lsd_worker.py calls sample_ddim(dit, sched, ...) directly without c_spec — it doesn't use LSDModel at all. The PR explicitly lists CLI exposure as out-of-scope. So even after this merges, we'd need a follow-up in lsd_worker.py to pass c_spec into sample_ddim for generation to actually use spectral conditioning. Same for training — our worker calls train_audio_diffusion(...) which now passes c_spec, so retraining after this PR lands would train a conditioned DiT, but inference wouldn't use it until we wire the worker.
Recommendation
Post a review requesting:
1. ruff format the new test file.
2. Rework the divergence tests — either train a tiny DiT in the fixture (a few steps) or assert at the v_pred level rather than the decoded audio. The current tests prove the plumbing exists but can't prove it works on an untrained model, and CI reflects that honestly.
3. Note the LSD Studio follow-up: lsd_worker.py needs --c-spec / --ref-audio args to actually exercise this at inference time.
The core code change is correct and low-risk (backward-compatible, no breaking changes to existing callers). Once the tests are fixed to pass on CI, it's mergeable.
