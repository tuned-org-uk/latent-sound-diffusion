# LSD: Sound-Production Framework (Alignment to LSD-studio)

> This document defines the **objectives** of Latent Sound Diffusion (LSD)
> as a sound-production tool and the **contract** between this repository
> (`latent-sound-diffusion`, the model core) and the commercial MVP
> application [`LSD-studio`](https://github.com/tuned-org-uk/LSD-studio)
> (the producer UX/UI).
>
> LSD is **not** the ALD-SC research artifact and has no falsifiable claim.
> It exists to let a sound producer train a model on a **sound archive**
> and explore novelty for integration into a production pipeline.

## 1. The producer workflow

A **sound producer** owns a library of samples (a *sound archive*) they
want to leverage — concretely `.wav` files placed in `data/`. LSD trains a
model on this archive to explore novelty of sound. Once trained, the
**model** is an inference-time sound-design tool that the producer
leverages in three complementary ways (A, B, C):

```
                  Sound archive (data/*.wav)
                            │
                            ▼
                  ┌─────────────────────┐
                  │  Train LSD model    │  (notebook 06: prior + graph
                  │  (graph decoder +   │   decoder + DiT, noise injection,
                  │   DiT)             │   non-repeatable SEED)
                  └─────────────────────┘
                            │  trained model artefacts
                            ▼
        ┌───────────────────┴───────────────────┐
        │        Inference-time model           │
        └───────────────────┬───────────────────┘
                            │
   ┌────────────┬───────────┼───────────┬────────────┐
   ▼ A          ▼ B                     ▼ C
┌────────┐  ┌──────────┐           ┌──────────────┐
│ Sound  │  │ Audio-   │           │ MIDI-        │
│ bank   │  │ condi-   │           │ drivinated   │
│ gen   │  │ tioned   │           │ synthe-  │
│       │  │ variants │           │ sis      │
└───────┘  └──────────┘           └──────────────┘

              │  • mix into a track       │

```

### 1.1 The three inference modes

**A. Sound-bank generation (unconditional).**
The model produces a **set of *output sounds*** that serve as a *baseline*
the producer can audition, select, and pick from. This is the default
creative surface: "give me N new sounds in the space of my archive".
Implemented today by `sample_ddim` + the graph decoder; this repository
exposes it as `generate_sound_bank(...)`.

**B. Audio-conditioned variants.**
The producer passes an **existing sound** (their own, or a bank output)
to the model, and the model generates **novelty / variants** of it —
perturbing, augmenting, or applying learned effects. Concretely: encode
the conditioning audio to its EnCodec latent, apply a controlled
perturbation (random walk / SDE bridge / classifier-free guidance toward
the conditioning latent), and decode. The chart conditioning $c_{spec}$
is then derived from the conditioned latent, so the graph decoder keeps
the result on the producer's archive manifold. Exposed as
`condition_on_audio(...)`.

**C. MIDI-driven synthesis.**
The producer passes a **MIDI file** (or live MIDI symbols) and the model
**synthesises those symbols** using the sounds generated by LSD — i.e.
pitch-shift and re-timbre the generated bank sounds to the MIDI note
sequence. This closes the loop with a traditional production pipeline.
Pitch/timing control lives in `LSD-studio`; this repository exposes a
thin `synthesize_midi(...)` adapter that maps MIDI note events to
pitch-shifted decodings of sampled latents.

### 1.2 The output sound bank and downstream uses

The **output sounds** produced by any of A/B/C form a *bank*: a numbered
set of audio clips. Per the objectives, the producer can:

- **Mix** them into a track (in `LSD-studio` / a DAW).
- **Feed them back** to the model for further generation (mode B with the
  bank output as input).
- **Concatenate** them and **add effects** — already demonstrated by
  notebooks 02 (overlap-and-add), 03 (BPS modulation + plugin effects),
  and 04 (latent-space concatenation).

## 2. Minimal alignment in this repository

To move LSD from an experimental phase toward a commercial MVP, this
repository exposes a single, stable inference contract in
`src/ald_sc/inference.py`:

```python
from ald_sc.inference import LSDModel

m = LSDModel(prior=prior, dit=dit, decoder=graph_decoder,
             schedule=sched, encoder=encoder, sample_rate=24000)

# A — baseline sound bank
bank = m.generate_sound_bank(n=8, steps=50, temperature=0.85, seed=None)

# B — audio-conditioned variants of a producer sound
variants = m.condition_on_audio(audio, n=4, strength=0.5, seed=None)

# C — MIDI-driven synthesis over a generated bank
render = m.synthesize_midi(midi_path="riff.mid", bank=bank, seed=None)
```

Design rules:

- **The model is the artefact.** Training (notebook 06 / `scripts/`) produces
  `prior`, `decoder`, `dit`. `LSDModel` bundles them and owns inference.
- **No training logic in `inference.py`.** It composes existing
  `sample_ddim`, the decoder, and the EnCodec encoder (per AGENTS.md §11).
- **`seed=None` means non-repeatable** everywhere — artistic exploration is
  a first-class requirement, not a debug mode (see §3).
- **MIDI synthesis is out of scope for the core.** The adapter here maps
  MIDI notes to pitch-shifted bank sounds; a full instrument/timbre model
  and the UX live in `LSD-studio`.

## 3. Non-functional (artistic) requirements

- **Fast artist training.** Training a model on the producer's own samples
  must be interactive-fast on CPU for small archives (minutes, not hours).
  Notebook 06 already targets this; further latency work belongs to
  LSD-studio's training UX.
- **Non-repeatable by design.** `SEED = None` and `NOISE_INJECT` make each
  run distinct; the *variation* is the product.
- **Stable contract.** `LSDModel`'s method signatures are the API
  LSD-studio consumes; breaking changes require a minor version bump and a
  matching LSD-studio issue.
